# Sigil

Authorization conformance testing for Soroban.

Soroban contracts decide who may do what through `require_auth`. That surface is
where the expensive bugs live: authorization demanded from the caller instead of
the owning address, a token transfer nobody asserted, an admin gate that any
address satisfies. Contract test suites rarely assert the shape of the
authorization tree at all, and nothing asserts that a client signs entries the
network will actually accept.

Sigil is two halves of one problem:

- **Contract side.** Declare the authorization surface in `sigil.toml`, then
  check the contract against it, first in the `soroban-sdk` test environment and
  then with signed probes on a live network.
- **Client side.** Check that an application's signing path produces auth
  entries the network accepts, using a mock SEP-43 signer.

## Status

Early. This repository is being built in the open and most of it does not exist
yet. What works today:

- `crates/sigil-auth` builds the signing payload for an address-credentials
  authorization entry: `SHA-256(XDR(HashIDPreimage::SorobanAuthorization))`.
  It is pinned byte-for-byte against a fixture generated by the official
  JavaScript SDK, so the two implementations cannot silently drift.

What does not exist yet: the `sigil.toml` parser, the sandbox harness, the CLI,
every check in [docs/CHECKS.md](docs/CHECKS.md), every probe in
[docs/PROBES.md](docs/PROBES.md), and the client-side package. The registries
are written first on purpose, so that each unit of work has a specification
before it has an implementation.

No claim in this README describes code that is not in the repository. If you
find one, it is a bug worth reporting.

## Why the signing payload comes first

Every on-chain probe is downstream of these bytes. A single wrong field or
misordered element produces a tool that confidently reports findings that are
not real, which is worse than having no tool. So the payload is implemented
first and validated against a known-good reference rather than against itself:

    cargo test -p sigil-auth

`fixtures/auth_preimage_v1.json` is generated by `@stellar/stellar-sdk` and is
not hand-written. The test decodes the invocation from that fixture, rebuilds
the preimage in Rust, and asserts both the XDR encoding and the SHA-256 match.

## Layout

    crates/sigil-auth      signing payload construction
    docs/CHECKS.md         sandbox check registry
    docs/PROBES.md         live-network probe registry
    fixtures/              reference vectors from the JS SDK
